# Adsflux Design System

How the brand ([BRAND_GUIDELINES.md](./BRAND_GUIDELINES.md)) is implemented in code. Stack: **React 19 + TypeScript + Vite**, styled with **CSS Modules on top of CSS custom properties**. No Tailwind, no UI kit. Live reference: **`/brand`**.

```
src/styles/tokens.css        every visual value: palette, tones, scales (the only file with brand hexes)
src/styles/base.css          element defaults: headings, <em> serif accent, links, focus, selection
src/styles/utilities.css     .display .label .highlight .accent .paper .visually-hidden
src/styles/reset.css         reset + global reduced-motion collapse
src/styles/fonts.ts          imports fonts.css (generated by `npm run fonts`: stable /fonts/ URLs, preloadable)
src/assets/assetRegistry.ts  every real image/video: variants, dimensions, alt, placement (see docs/assets/)
src/styles/breakpoints.ts    breakpoint values for JS (CSS uses the same literals)
src/lib/motion.ts            motion constants for JS (mirror of the CSS motion tokens)
src/lib/gsap.ts              loadScrollTrigger(): GSAP + ScrollTrigger, loaded after page load when idle
src/lib/theme.ts             colour mode store (light/dark): <html data-theme>, localStorage, OS preference
src/hooks/useTheme.ts        { theme, setTheme } for React (useSyncExternalStore over lib/theme)
src/components/ui/           primitives
src/components/motion/       motion primitives
src/components/sections/     reusable page sections (CtaSection)
src/components/layout/       RootLayout, SiteHeader, ThemeToggle, MobileMenu, SiteFooter, ScrollManager
src/features/*               services · showcase · work · testimonials · pricing · contact
src/pages/*                  home · brand · not-found
```

Flow: **tokens → primitives → compositions**. Never skip a level.

## 1. Tokens

### Four tiers

1. **Brand palette** (`--brand-*`): the six light colours and three derived tints (`--brand-ink-soft`, `--brand-cream-soft`, `--brand-cream-dim`); the six Midnight Editorial dark colours (`--brand-midnight`, `--brand-slate`, `--brand-mist`, `--brand-electric`, `--brand-ember`, `--brand-graphite`) and three derived dark tints (`--brand-electric-ink`, `--brand-slate-raised`, `--brand-dusk`); two status colours (`--status-danger-on-light`, `--status-danger-on-dark`). Referenced **only** in `tokens.css`. Documented exceptions: `Logo.module.css` (fixed monogram colours), the palette swatches on `/brand`, and the two `theme-color` hex values in the `index.html` bootstrap script.
2. **Theme tokens** (`--background`, `--foreground`, `--surface`, `--surface-elevated`, `--muted-foreground`, `--border`, `--border-strong`, `--primary`, `--primary-foreground`, `--primary-ink`, `--accent`, `--accent-foreground`, `--danger`, plus `--scheme`, `--grain-blend`, `--texture-opacity-background/-surface`, `--line-art-opacity`): the page palette for the active **mode**, switched by `data-theme="light|dark"` on `<html>`. They feed the cream and blue tones. **Components never read them**: inside a cobalt band, `--foreground` would still be the page's ink.
3. **Semantic tokens** (`--color-*`): what components use. Re-mapped per tone, in both modes.
4. **Scales**: type, space, radius, shadow, motion, z-index. Mode- and tone-independent.

Why the CTA stays cobalt in dark mode: Electric `#5268FF` is the dark-mode primary for shapes, large type and shadows, but no palette colour reaches 4.5:1 on it (cream 3.87, midnight 4.22, ink 4.08). The button keeps cobalt + cream (6.77:1) and hovers to Ember.

**Rules of thumb**

- `--color-accent` is a **fill** (always paired with `--color-on-accent`). `--color-accent-ink` is **ink** for text, rules and indexes. It is already contrast-safe in every tone (that is why peach uses ink).
- `--color-highlight` is a **fill** behind `--color-on-highlight` text (the `.highlight` utility, `Badge variant="highlight"`, `Stamp`, pressed chips). Orange never appears as text on cream or cobalt.
- `--color-shape-1/2` are for **decorative graphics** only (bursts, placeholder art, dots, offset shadows), never text.

### Tones are scoped

```html
<section data-theme="cobalt">…</section>   <!-- re-themes everything inside -->
```

`[data-theme='cream' | 'blue' | 'peach' | 'cobalt' | 'orange' | 'ink']` works on **any element** below `<html>`, and base.css makes every toned element paint its own `background-color` and `color`. In React use `<Section tone="cobalt">`; for a sub-block (a service module, a placeholder) put `data-theme` on the element. The page itself is the cream tone (Paper Cream in light mode, Midnight in dark mode).

### Colour mode (light / dark)

`<html data-theme="light|dark">` is the **mode**; the six values above are **tones**. They never share an element, so the values never collide. Every tone has a light and a dark rendering, and components don't change: they keep reading `--color-*`.

- **First paint.** An inline script in `index.html` (before CSS and the bundle) reads `localStorage['adsflux-theme']`, else `prefers-color-scheme`, and sets `data-theme`, `style.colorScheme` and `<meta name="theme-color">`. No flash, including on the static per-route HTML the SEO plugin writes.
- **Runtime.** `src/lib/theme.ts` is a tiny external store (`getTheme`, `setTheme`, `subscribeToTheme`); `useTheme()` wraps it with `useSyncExternalStore`. No provider is needed. With no saved choice the site follows the OS live; a choice is saved; choosing the mode the OS already asks for clears the saved value, so the site follows the system again. Storage and other tabs stay in sync (`storage` event). Blocked storage only means the choice isn't remembered.
- **Toggle.** `ThemeToggle` (in `SiteHeader`, every breakpoint, so it also serves the mobile menu): a 44px pill, `aria-pressed` = dark mode, accessible name "Dark mode", half-filled disc that turns 180°.
- **Transition.** A 280 ms cross-fade via the View Transitions API (`::view-transition-*` in base.css). No per-property colour transitions (they would fight component transitions). Instant under `prefers-reduced-motion` or where unsupported.
- **`color-scheme`** comes from the tone (`var(--scheme)` for cream/blue), so native controls, scrollbars and autofill match in both modes.
- **Imagery is never filtered.** No `invert()`, no blend modes on photos: campaign images, the hero cut-out cards and phone keep their colours. Only token-driven graphics change (hero blob → Electric, brush strokes and disc → Ember, orbit → Electric ink at `--line-art-opacity` 0.8).
- **Paper texture** multiplies into light tones and screens out of dark ones (`--texture-blend`), so the grain survives on midnight.
- **Adding a semantic colour:** cream and blue usually need nothing new if they can use a theme token; otherwise add it to `:root, [data-theme='cream']`, `blue`, and the light **and** dark block of peach, cobalt, orange and ink. Check its contrast in all twelve renderings.
- **Reading the mode in JS** is for content only (the `/brand` swatch labels, the Scalvo preview's starting theme), never for picking colours.

Never hard-code a background to fake a tone, and never read the tone in JS to pick colours. Let tokens cascade.

### Element defaults (base.css)

- `h1`–`h6`: Space Grotesk 500, tight leading and tracking. `h1` = `--text-4xl`, `h2` = `--text-3xl`, `h3` = `--text-2xl`, `h4` = `--text-xl`.
- **The signature:** `<em>` inside `h1–h4`, `p` or `blockquote` switches to **Instrument Serif italic** (400). Inside headings it is scaled to 1.08em so the serif optically matches the grotesk. Write `Campaigns that <em>earn the scroll.</em>`.
- Links: underlined in `--color-accent-ink`, 1px → 2px on hover.
- `:focus-visible`: 2px `--color-focus` outline, 3px offset. `::selection`: highlight fill.
- `html` has `scroll-behavior: smooth` (auto under reduced motion) and `scroll-padding-top` = header height + 1rem, so anchor targets clear the sticky header.

### Space, layout, shape

- **Spacing:** `--space-1 … --space-32` on a 4px base.
- **Section rhythm:** `--section-space-sm/md/lg` (48→80 / 72→136 / 88→176px). `<Section spacing>` uses these.
- **Containers:** `sm` 42rem (forms, prose) · `md` 64rem · `lg` 80rem (default) · `xl` 96rem (editorial sections; every home section uses it).
- **Gutter:** `--gutter` (20 → 48px). **Grid gap:** `--grid-gap` (16 → 32px). **Header:** `--header-height` 4.75rem.
- **Radius:** `--radius-none` 0 (frames, modules, panels, menus, inputs) · `--radius-xs` 2px (focus rings) · `--radius-pill` (buttons, tags, chips, dots, stamp). **Nothing else.**
- **Shadows:** `--shadow-offset` (10px 10px solid `--color-shape-2`, the editorial print shadow for lifted images) · `--shadow-overlay` (floating layers such as the dropdown panel only).
- **Z-index:** `--z-base` 0 · `--z-raised` 10 · `--z-dropdown` 100 · `--z-sticky` 200 · `--z-overlay` 300 · `--z-modal` 400 · `--z-toast` 500.

### Conventions

- Primitives extend the native element's props, spread `...props`, and merge `className` last via `cn()`.
- Appearance is controlled by typed `variant` / `size` / `tone` unions, never by style props.
- **One primary button per view.** Everything else is `secondary` (outlined pill) or `ghost` (underlined text).
- Forward-moving CTAs get `withArrow` (an inverted circle with ↗ that turns 45° on hover).
- **No cards by default.** Services are modules, testimonials and CTAs are typography, work is a collage.
- Global CSS sits in cascade layers (`reset, base, utilities`). CSS Modules are unlayered and always win, so **never use `!important`** (the only exception is the reduced-motion block in `reset.css`).
- The lint rule `jsx-a11y/prefer-tag-over-role` is off on purpose: `role="img"` on inline SVG and `role="status"`/`"alert"` live regions are the correct patterns.

## 3. Layout principles

1. **Cream leads, tones punctuate.** Plan the tone rhythm before building: mostly cream, cobalt for the big moments, blue/peach supporting, one orange strip, at most one ink band. Home: cream hero → orange ticker → cream services → ink showcase → cobalt philosophy → blue work → cream clients → cobalt contact → blue footer. Use `divider` if two same-tone sections must touch.
2. **12-column, asymmetric.** `SectionHeading layout="split"` puts the title in 8 columns and the aside in the last 4 (from 1024px). Collages use irregular spans and staggered vertical offsets.
3. **Typography-led.** One big sentence per section beats three paragraphs. Pair a grotesk heading with one serif `<em>` phrase.
4. **Collage over grids.** Overlap frames, mix ratios, add a parallax detail frame or a stamp. Keep overlaps from covering captions or text.
5. **Number things.** Sections get `Eyebrow index="01"`; lists and pieces get mono `(01)` indexes.
6. **The header is sticky and opaque, in normal flow.** The first section does **not** need header offset padding. Anchor targets are handled by `scroll-padding-top` (and `scroll-margin-top` where needed).
7. **Whitespace is a feature.** Use `spacing="lg"` for key sections. Use `Container size="xl"` for editorial sections and `sm` for forms and long prose.

## 4. Responsive

- Mobile-first. Verify at **360/390, 768, 1024, 1440** widths, with **no horizontal page scroll** at any of them. Sections that hold oversized type or parallax (`HomeHero`, `PhilosophySection`, `CtaSection`) set `overflow: hidden`.
- Grid tracks that hold big type use `minmax(0, Nfr)`. A bare `fr` track won't shrink below the longest word.
- Below 1024px the header nav collapses to the cobalt `MobileMenu`; the header CTA appears from 640px.
- Collages simplify on mobile (e.g. the `CampaignCollage` stills become an offset two-column flow, reels pair up 2-up). Keep the composition; drop the complexity.

## 5. Motion

**Principle: motion tells the story, it never decorates.** Small distances, expo-out easing, play once. Motion should be felt, not watched.

| Need | Use |
|---|---|
| Block entrance | `<Reveal delay>` |
| List/grid entrance | `<Stagger as="ul">` + `<StaggerItem as="li">` |
| Headline reveal | `<TextReveal trigger="mount">` for the hero, `"inView"` elsewhere. One or two per page |
| Image entrance | `<ImageReveal from>` around a `MediaFrame` |
| Layered depth | `<Parallax distance>` on collage frames; `axis="x"` for opposing headline lines (philosophy) |
| Scroll storytelling | `<ScrollHighlightText>` for one manifesto passage |
| Ticker | `<Marquee items>` inside an orange band |
| Video creatives | `MediaFrame videoSrc + poster` |
| Hover | CSS transitions with motion tokens: arrow chip and logo burst turn 45°, underline thickens, media zooms 1.045 (`.media-hover`), collage pieces lift with an offset shadow, service numbers turn italic |
| Ambient | `Burst spin` and `Stamp` rotate slowly (24s / 22s loops). One or two per view |

**Technology**

- **motion** (`motion/react`) for component animation. `MotionProvider` uses `LazyMotion` with **async-loaded** `domAnimation` and `strict`. **Always `m.*`, never `motion.*`.**
- **GSAP + ScrollTrigger** only for scroll-linked work (`Parallax`, `ScrollHighlightText`), always through `loadScrollTrigger()` from `@/lib/gsap` (a dynamic import, so it never enters the main bundle). Wrap tweens in `gsap.context()` and `revert()` on cleanup; guard against unmount before the import resolves.
- **Lenis is intentionally not installed.** Smooth-scroll hijacking hurts accessibility and input latency, and the scenes don't need it. Only add it for a page whose ScrollTrigger choreography visibly stutters without it; lazy-load it on that page and disable it under reduced motion.

**Reduced motion** (`prefers-reduced-motion: reduce`)

- `MotionConfig reducedMotion="user"`: transform animations are skipped; opacity fades remain.
- `Parallax` and `ScrollHighlightText` render static; `ImageReveal` shows the image without the wipe; `MobileMenu` fades instead of wiping (`usePrefersReducedMotion`).
- CSS loops stop: `Marquee` wraps and stops (duplicate track hidden), `Stamp` and `Burst spin` stop.
- `AutoplayVideo` never autoplays; it shows the poster with its play/sound controls.
- `reset.css` collapses all CSS animation and transition durations; CSS smooth scroll is disabled.

**Gotchas**

- **Clipped elements never intersect.** Never put `whileInView` on an element that starts fully clipped inside an `overflow: hidden` mask; the IntersectionObserver never fires. `TextReveal` observes the visible wrapper span and drives the masked words through variants.
- **`ImageReveal` observes the outer, unclipped element.** The clip layer starts at `inset(100% …)` (fully clipped), so the `whileInView` sits on the outer `m.div` and the clip and zoom layers follow via variants. Keep that structure. The clip layer also needs `overflow: hidden`, because `clip-path` doesn't clip the zoomed layer's scrollable overflow.
- `clip-path` animations are not transforms, so `reducedMotion="user"` does not skip them. `ImageReveal` therefore renders the image directly under reduced motion, and `MobileMenu` swaps its clip-path wipe for a plain fade. Do the same for any new clip-path animation.

**Budget.** Initial JS ≤ 120 KB gzip (currently ~119 KB). The motion engine and GSAP load on demand; check `npm run build` after adding any animation dependency.

## 6. Accessibility

- WCAG 2.2 AA in **both modes**. Use the contrast tables in BRAND_GUIDELINES. Orange is never text on cream or cobalt; ink is never text on cobalt; cream is never text on blue. In dark mode Electric `#5268FF` is never small text or button text; accent text uses Electric ink.
- The theme toggle is a `<button aria-pressed>` named "Dark mode"; its focus ring is the tone's `--color-focus`.
- Skip link, landmarks (`header`, `nav[aria-label]`, `main#main`, `footer`), one `h1` per page.
- `:focus-visible` rings (`--color-focus`, tone-aware). Interactive targets ≥ 44px (`Button md/lg`, nav links, menu button). Known smaller target: `Button sm` (36px, header only); it stays above the WCAG 2.2 minimum of 24px, but don't add more. Showcase filter chips are 44px.
- `Field` wires `label`, `aria-describedby`, `aria-invalid` and `role="alert"` errors; the form uses `role="status"` for success.
- `Dropdown` follows the WAI-ARIA disclosure pattern: Escape returns focus; focus leaving, an outside click or link selection closes it.
- Filter chips are `<button aria-pressed>` in a labelled `role="group"`.
- Animated headlines keep a screen-reader copy (`.visually-hidden`) with the animated words `aria-hidden`. Decorative graphics (`Burst`, `Stamp`, `PlaceholderArt`, the hero collage) are `aria-hidden`.
- Photography needs real `alt` text; `alt=""` only when purely decorative. Videos get `alt` as their accessible label.

## 7. Performance

- **Budget:** initial JS ≤ 120 KB gzip; currently ~119 KB (React + react-router declarative + motion core + the ~0.6 KB theme store and toggle). The theme bootstrap is an inline script in `index.html`, outside the bundle.
- Routes other than home use `React.lazy`. GSAP and the motion feature bundle load on demand.
- Fonts: latin + latin-ext woff2 served from stable `/fonts/` URLs (`npm run fonts` → `public/fonts/` + `src/styles/fonts.css`). The three above-the-fold faces (Instrument Serif roman + italic, Space Grotesk) are preloaded in `index.html`, which took mobile CLS from 0.145 to 0.
- Routing uses declarative `BrowserRouter` on purpose (~13 KB vs ~31 KB for the data router). Revisit only if routes need loaders.
- Media: every image goes through the asset pipeline (`npm run assets`) and registry: AVIF + WebP variants, intrinsic `width`/`height`, per-slot `sizes`. Only the hero photograph is `priority` (eager, `fetchpriority="high"`, preloaded in `index.html`, **no entrance animation**, because an animated LCP image can't paint until JS runs). Everything else is `loading="lazy" decoding="async"`. Videos use `preload="none"`, play only while visible (the poster is a lazy `<picture>`, not an eager `poster=`), and only one has sound at a time.
- GSAP is fetched only after `load` + idle (`loadScrollTrigger()`), so it never competes with the LCP image.
- Measured (Lighthouse 13, home): desktop Performance 100, CLS 0, LCP 0.6 s; mobile Performance 96 (simulated) / 94 (DevTools throttling), CLS 0. See `docs/assets/ASSET_INVENTORY.md`.
